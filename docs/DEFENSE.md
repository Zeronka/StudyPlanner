# Разбор проекта для выступления

## Вступление — 30 секунд

«StudyPlanner — локальный планировщик учебных задач. Пользователь задаёт название, предмет и срок, меняет состояние, редактирует и удаляет задачи. Сервер написан на ASP.NET Core Minimal API, основной интерфейс — HTML/CSS/JavaScript с fetch. Данные записываются в JSON-файл. Дополнительно есть компонент Blazor».

## Показ — 3–5 минут

1. Открыть главную страницу и добавить задачу «Разобрать HTTP» по предмету ASP.NET.
2. Изменить название, отметить задачу готовой, включить фильтр. Объяснить отсутствие полной перезагрузки страницы.
3. Открыть `/api/tasks`: браузер показывает JSON. Это ответ API, не HTML-разметка.
4. Открыть `/api/stats` и `/razor`.
5. Перейти к коду на GitHub. Открывать файлы в порядке ниже. Само приложение при этом работает на ПК колледжа: GitHub хранит исходники и документацию.

## 1. Program.cs: конфигурация и маршруты

`WebApplication.CreateBuilder(args)` подготавливает приложение. В `builder.Services` регистрируются зависимости: один `TaskRepository`, фабрика HTTP-клиентов и интерактивные Razor-компоненты. После `Build()` настраивается конвейер запросов.

Middleware с `app.Use` оборачивает следующий обработчик: запускает Stopwatch, вызывает `await next(context)` и в `finally` пишет журнал. Если исключение прервало запрос, в этой записи используется начальный статус 500; middleware не реализует собственный JSON-обработчик всех исключений.

`UseDefaultFiles` позволяет отдавать index.html по `/`, `UseStaticFiles` отдаёт CSS и JavaScript. `UseAntiforgery` нужен для поддержки компонентов; сам по себе этот вызов не добавляет авторизацию и не означает, что все Minimal API защищены от CSRF.

`MapGet`, `MapPost`, `MapPut`, `MapDelete` связывают HTTP-метод и путь с обработчиком. `{id:int}` ограничивает маршрут целым числом. Данные JSON привязываются к `TaskInput`; репозиторий приходит из DI.

`Validate` проверяет обязательность и длину полей до изменения хранилища. При ошибке возвращается `ValidationProblem` со статусом 400. При POST возвращается `Created`: тело задачи и Location. PUT возвращает обновлённую задачу; DELETE — 204, без JSON-тела.

## 2. Models/StudyTask.cs: данные

`StudyTask` — record с Id, Title, Subject, необязательной датой DueDate и флагом IsCompleted. `TaskInput` — отдельная входная модель без Id: идентификатор назначает сервер. `DateOnly?` означает дату без времени, которая может отсутствовать. Record здесь используется как неизменяемая запись: при обновлении создаётся новая задача.

## 3. Services/TaskRepository.cs: хранение

Конструктор находит папку App_Data. Если JSON уже существует, читает его; иначе создаёт демонстрационный список в памяти. Дополнительно проверяет уникальность и положительность Id.

`SemaphoreSlim(1,1)` допускает одну операцию за раз. Каждый метод делает `WaitAsync`, а `finally` гарантирует `Release`. Это важно при параллельных HTTP-запросах.

`GetAllAsync` отдаёт копию массива. Create/Update/Delete готовят новый список, вызывают `SaveAsync`, и только затем меняют рабочий список `_tasks`. Ошибка записи не должна незаметно заменить список в памяти на несохранённый.

`SaveAsync` пишет `tasks.json.tmp`, затем заменяет `tasks.json`. Это сокращает риск частичной записи, но не является обещанием полноценной долговечности транзакций при любом отключении питания. Для промышленного многопроцессного сервера нужна СУБД.

## 4. wwwroot/app.js: клиент

`request` выполняет fetch, добавляет JSON Content-Type и проверяет `response.ok`. Ответ 204 обрабатывается отдельно: у него нет JSON-тела. Сообщения валидации объединяются для показа пользователю.

Обработчик submit делает `preventDefault`, собирает поля, выбирает POST или PUT, сериализует JSON и вызывает `mutate`. `mutate` блокирует повторное действие через busy, показывает состояние сохранения, после ответа заново получает список и в finally снимает блокировку.

`render` строит DOM и навешивает обработчики кнопок. Пользовательский текст выводится через textContent. Фильтр главной страницы работает в браузере по уже загруженному массиву. Отдельно API поддерживает свои query-параметры фильтрации. Счётчики главной страницы считаются на клиенте; `/api/stats` — отдельный серверный маршрут для демонстрации.

## 5. TaskList.razor: компонент

`@page "/razor"` задаёт маршрут, `@rendermode InteractiveServer` — выполнение интерактивного компонента на сервере. `@inject` получает фабрику HttpClient и NavigationManager из DI.

После первого интерактивного рендера `OnAfterRenderAsync` вызывает `LoadAsync`; HTTP-клиент получает тот же API, а `@foreach` выводит задачи. Здесь HTTP-запрос выполняется серверной частью Blazor, в отличие от fetch основного JavaScript-клиента. Компонент `.razor` не является страницей Razor Pages `.cshtml`.

## Завершение

Назвать три ограничения: один процесс, JSON вместо СУБД, нет пользователей. Предложить развитие: SQLite/EF Core, авторизация и тесты. Объяснять только то, что удалось понять; перед выступлением пройти тренировку из PRACTICE.md.
