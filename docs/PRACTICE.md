# Тренировочная практика ASP.NET и AJAX

Точное практическое условие экзамена пока неизвестно. Ниже упражнения по уже имеющемуся проекту. Это не обещание состава билета. Делать сначала без подсказок, затем сверяться с кодом.

## Минимум — объяснить и повторить

1. За 5 минут нарисовать цепочку: форма → fetch → маршрут → валидация → репозиторий → JSON → ответ → DOM.
2. Без заучивания перечислить методы CRUD и коды 200/201/204/400/404.
3. Найти, где задаются маршруты, проверяется длина, сохраняется файл и выводится пользовательский текст.
4. Объяснить различие JavaScript fetch и HTTP-запроса из InteractiveServer-компонента.

## 20 минут — изменить сервер

Задача: добавить GET `/api/tasks/pending`, возвращающий только невыполненные задачи. Сначала написать самостоятельно.

Подсказка: использовать GetAllAsync и Where(t => !t.IsCompleted). Существующий `{id:int}` не перехватит слово pending. Дать 200 и массив, в том числе пустой.

## 20 минут — изменить интерфейс

Добавить кнопку «Обновить» на главную страницу. По нажатию заново вызвать GET списка, показать ошибку при недоступности сервера, не перезагружать страницу целиком.

Подсказка: использовать load и message; не вставлять пользовательский текст в innerHTML. Учесть состояние busy, чтобы не дублировать действие.

## 30 минут — новое поле

Добавить приоритет 1–3. Продумать StudyTask и TaskInput, Validate, форму HTML, сборку JSON в app.js, отображение и сохранение. Затем объяснить, что произойдёт со старыми файлами JSON без поля. Перед изменением сделать копию исходников и данных.

Подсказка: не ограничиваться одним полем HTML; на сервере тоже нужна проверка диапазона. Выбрать и объяснить значение по умолчанию/миграцию старых записей.

## 15 минут — найти ошибку

Объяснить, почему нельзя всегда вызывать response.json() после DELETE с 204. Почему проверки required в браузере не заменяют серверную Validate? Почему Singleton не делает JSON-хранилище подходящим для нескольких процессов?

## 40 минут — повторить с нуля

В новой папке создать простое ASP.NET-приложение со списком книг: GET списка, GET по Id, POST, PUT и DELETE; HTML-форма и fetch для добавления. На первом этапе использовать память и честно назвать потерю данных после перезапуска. Не копировать целиком StudyPlanner, воспроизвести маршрут запроса и объяснить каждую часть.

## Порядок подготовки

День 1: запуск и схема запроса. День 2: Program.cs и HTTP. День 3: модели и репозиторий. День 4: app.js и AJAX. День 5: Razor/Blazor и пробная защита. Перед экзаменом: запуск на Windows колледжа, демонстрация и ответы без чтения шпаргалки.
